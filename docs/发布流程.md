# DeepMei 发布流程（发版检查清单）

> 每次发布前必读本文档。
> 适用仓库：`/Users/shensunfeng/DeepMei`（iOS + Watch 版）
> 最近一次发布：v2.8.4（build 10），2026-08-17

---

## 一、版本号规则

| 项 | 含义 | 规则 |
| --- | --- | --- |
| `MARKETING_VERSION` | 对外版本号（用户在设置里看到的） | 语义化：`主版本.次版本.修订号` |
| `CURRENT_PROJECT_VERSION` | build 号（内部递增） | **每次发版 +1** |

- 主 App 与 Watch App 的版本号必须**保持一致**。
- 涉及审核的新功能/大改动 → 次版本号 +1；紧急修复 → 修订号 +1；build 号每次发版无条件 +1。

## 二、发布前必改清单（逐项勾选）

### 1. 更新日志（Release Notes）
- [ ] 在仓库根目录 `CHANGELOG.md` 顶部追加本次版本条目（日期、版本号、build 号、功能/修复列表）
- [ ] 同步到 TestFlight / App Store Connect 的「What's New」（以用户视角写，别贴 commit message）
- [ ] 若涉及用户协议 / 隐私政策变更：更新 `DeepMei/user-agreement.md`、`DeepMei/privacy-policy.md`（以及 `docs/privacy-policy.html`）

### 2. 版本号与 build 号（**最容易漏**）
文件：`DeepMei.xcodeproj/project.pbxproj`（共 **8 处**，4 组 × Debug/Release）：

| 目标 | MARKETING_VERSION | CURRENT_PROJECT_VERSION |
| --- | --- | --- |
| 主 App DeepMei | Debug + Release（2 处） | Debug + Release（2 处） |
| Watch App DeepMeiWatch | Debug + Release（2 处） | Debug + Release（2 处） |

快速修改命令（以 2.8.5 / build 11 为例）：
```bash
sed -i '' 's/MARKETING_VERSION = 2.8.4;/MARKETING_VERSION = 2.8.5;/g' DeepMei.xcodeproj/project.pbxproj
sed -i '' 's/CURRENT_PROJECT_VERSION = 10;/CURRENT_PROJECT_VERSION = 11;/g' DeepMei.xcodeproj/project.pbxproj
```
改完务必 `grep -c "MARKETING_VERSION = \|CURRENT_PROJECT_VERSION = "` 确认数量，别漏 Watch。

### 3. 文案与名单
- [ ] `DeepMei/CreditsView.swift`：测试人员名单（每次发版前确认有无增删）
- [ ] `DeepMei/HallOfFameView.swift`：名人堂成员（如有新人加入）
- [ ] `DeepMei/AboutView.swift`：版本号**自动读取** bundle（`CFBundleShortVersionString`），无需手动改

### 4. 工程配置检查
- [ ] 部署目标：主 App `IPHONEOS_DEPLOYMENT_TARGET = 18.6`、Watch `WATCHOS_DEPLOYMENT_TARGET = 10.0`
- [ ] 设备支持：`TARGETED_DEVICE_FAMILY`（iPhone/iPad 支持是否变化）
- [ ] 合规项：新增网络请求需确认「非加密合规」；新增数据收集需更新 `DeepMei/PrivacyInfo.xcprivacy`
- [ ] 签名：`DEVELOPMENT_TEAM = C8ZTY29S4K`，Archive 时自动签名正常

### 5. 发版前自测
- [ ] iPhone / iPad 双端跑一遍核心链路（首页、活动、查询、签到、我的树莓、名人堂）
- [ ] Watch App 编译并跑通（社员二维码、抽卡）
- [ ] 深色模式、iOS 26 液态玻璃安全区
- [ ] 全新安装 + 覆盖安装各一次

## 三、提交与发布步骤（遵循仓库 commit 规范：中文、详细易懂）

1. 提交功能代码（分门别类：`feat(模块): ...` / `fix(...): ...` / `perf(...): ...`）
2. 更新 `CHANGELOG.md`
3. 版本号升级提交（**单独一个 commit，只改 pbxproj**）：
   `chore: 版本号升级到 2.8.5（build 11）`
4. Xcode Archive → 上传 TestFlight / App Store Connect
5. 正式发布时提交：
   `release: 推送 v2.8.5 正式版本`
