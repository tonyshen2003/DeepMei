## 视频播放修复：飞书 tmp_url 不支持 Range 请求

### 问题
AVPlayer 直接用飞书 `tmp_url` 创建 `AVPlayerItem` 会失败（显示带斜杠的播放键）。原因是 AVPlayer 用自己的 HTTP 栈发 byte-range 请求做流式加载，飞书 `tmp_url` 不支持 Range 请求。图片不受影响因为 `FeishuAsyncImage` 用 `URLSession.data(for:)` 整体下载。

### 修复
**MemberService.swift**：新增 `downloadVideoToTempFile(from:)` 方法，复用 `downloadTempMedia` 的 `batch_get_tmp_download_url` 换链逻辑，下载视频 Data 后写入 `FileManager.default.temporaryDirectory` 临时文件，返回本地文件 URL。

**MyRaspberryView.swift** `VideoPlayerView` 重写：
- `setupPlayer()` 改为 `async`，先调用 `downloadVideoToTempFile` 下载到本地
- 用本地文件 URL 创建 `AVPlayerItem`（本地文件无 Range 请求问题）
- UI 新增下载中状态（"下载中…" + ProgressView），三态：下载中 → 播放/缓冲 → 失败
- `loadFailed` 判断条件修复：`if let player, !loadFailed` 确保 player 存在但加载失败时也显示错误提示
- `cleanup()` 新增临时文件清理（`FileManager.removeItem`）

### 视频下载失败排查：batch_get_tmp_download_url 返回空时 fallback 到 download URL
**原因分析**：飞书 `tmp_url` 是 `batch_get_tmp_download_url` 接口本身，不能直接下载；对该视频调用换链 API 返回 code=0 但 `tmp_download_urls` 为空，可能是视频 file_token 没有通过该接口获取临时下载链接的权限。

**MyRaspberryView.swift** 数据模型：
- `WorkItem` 字段拆分：`tmpURL`（batch 接口）+ `downloadURL`（`/download` 接口）
- `init(from decoder:)` 和 `LarkValue.workItems` 同时解析保存 `tmp_url` 和 `url` 两个字段
- `ImageWorkCard` 仍用 `tmpURL` 走现有 `downloadTempMedia` 图片下载逻辑
- `VideoWorkCard` 将 `tmpURL` 和 `downloadURL` 同时传给 `VideoPlayerView`

**MemberService.swift** 视频下载重构：
- `downloadVideoToTempFile(tmpURLString:downloadURLString:)`：
  1. 先尝试 `batch_get_tmp_download_url` 换链获取真正的临时下载链接
  2. 换链失败或返回空时，fallback 用 `downloadURL`（`/open-apis/drive/v1/medias/{file_token}/download`）+ `Authorization` 头直接下载视频二进制数据
  3. 写入临时文件并返回本地 URL
- `downloadVideoData(from:originalURL:)`：下载时携带 `Authorization: Bearer tenant_token`，保留原始扩展名写入临时目录
- 所有失败路径打印完整响应体（前 500 字符）到控制台，便于进一步诊断

1. 添加 `import Combine`（与 QRScanner.swift 一致，确保 Combine 类型直接可见）
2. CameraManager 类声明加 `nonisolated`：`nonisolated final class CameraManager`（退出默认 MainActor 隔离，该类大量使用后台 DispatchQueue）
3. `CaptureMetadata` 加 `Sendable` 一致性
4. `SaveResult` 枚举从 CameraManager 内部移出到顶层，加 `Sendable` 一致性

### 严重 Bug 修复：拍照后闪退回首页
**现象**：按快门拍照后 App 直接回到"首页"（Tab 1），实为 App 闪退后重开。
**根因（两个）**：
1. **Swift 6 并发崩溃**：`photoOutput(_:didFinishProcessingPhoto:)` 由 AVFoundation 在后台相机队列回调，但 `CameraManager` 因 `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` 被隐式 `@MainActor` 隔离 → 跨隔离调用触发运行时崩溃。
2. **内存峰值闪退**：高清照片（如 48MP）全分辨率解码 + 再渲染水印，内存峰值可能触发 Jetsam 杀死进程。
**修复**（DirectorCameraView.swift）：
1. `photoOutput` 回调改为 `nonisolated`，所有 `self` 捕获改为 `[weak self]`
2. `extractMetadata` + 三个数值解析辅助方法改为 `private nonisolated static`
3. 抽取 `handleCapturedPhoto(_:metadata:)` 在主线程渲染+更新状态+停止+保存
4. `WatermarkRenderer.render` 增加 `downscaled(_:maxEdge:)` 将长边限制为 2400px，改用 `UIGraphicsImageRenderer`（较 `UIGraphicsBeginImageContextWithOptions` 更高效），避免内存峰值

### 用户反馈复现："拍照/重拍后跳回首页" 再次排查（2026-07-27 晚）
**结论**：该现象并非页面主动跳转，而是 App **闪退后重开**（重开落在 Tab 0 = 首页），与上方"严重 Bug 修复"为同一症状。**上次修复不完整**：
- 上次只把 `photoOutput(_:didFinishProcessingPhoto:)` 回调改成 `nonisolated`，但 `CameraManager` 仍被项目 `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` 隐式标记为 `@MainActor`；其 `configure()/capture()/start()/stop()/setZoom()/focus()/flipCamera()` 的 `cameraQueue.async` 闭包里仍直接访问 `@MainActor` 存储属性 `session`/`photoOutput`/`currentDevice` → **跨 actor 数据竞争**。
- 点快门 → `capture()` 在 cameraQueue 访问 `self.photoOutput`；点重拍 → `resetCapture()→start()` 在 cameraQueue 访问 `self.session.startRunning()`。两者都触发后台跨 actor 访问 → 运行时 trap → 闪退 → 重开到首页。这解释了"拍照和重拍都会跳回首页"。
- 叠加：水印 `renderCinemaSlate` 仍在主线程同步执行且持有全分辨率 `originalImage`，内存峰值仍可能触发 Jetsam（上次记的第二因）。

### 新增功能：取景器拍照记录拍摄地点（GPS → 场记卡片 + EXIF）
**需求**：拍照时记录位置，把 GPS 经纬度写入照片 EXIF，并把经纬度转成人类可读文字（如「📍 北京市 朝阳区」「📍 San Jose, United States」）印在场记卡片底部。
**改动**（DirectorCameraView.swift + DeepMei.xcodeproj/project.pbxproj）：
1. 新增 `LocationService`（`NSObject, CLLocationManagerDelegate`，`lastLocation` 由 delegate 经 `DispatchQueue.main.async` 写回主线程）→ `CameraManager` 持有 `private let locationService`，`.task` 授权后调 `startLocationServices()` 请求"使用期间"定位并启动更新。
2. `CaptureMetadata` 增 `latitude/double?`、`longitude/double?`、`locationText/String?`（带默认 nil，向后兼容既有初始化）。
3. `photoOutput` 回调主线程读取 `lastLocation`；有位置则 `CLGeocoder.reverseGeocodeLocation` 反查，`CameraManager.placeName(...)` 把中国格式化为"省/市 区"、海外为"城市, 国家"，失败回退"纬度, 经度"；结果写入 `locationText = "📍 " + place` 后渲染。
4. `renderCinemaSlate` 场记卡片加底部青色地点行（`slateHeight` 0.16→0.18 留出空间）；`CapturedPreview` 也展示地点文字。
5. 存入相册时 `embedGPSData` 用 `CGImageDestination` 把 GPS IFD（经纬度 + Ref + UTC 日期戳）写入 JPEG EXIF；无 GPS 时回退普通 JPEG。需 `CoreLocation/ImageIO/UniformTypeIdentifiers` 三个 import。
6. pbxproj 两处 `INFOPLIST_KEY_NSLocationWhenInUseUsageDescription` 由空串改为实际用途说明（原先为空会导致定位权限弹窗无文案/可能被拒）。
**注意**：纯函数 `placeName/coordsText/embedGPSData` 标 `nonisolated`；`LocationService` delegate 方法标 `nonisolated` 并主线程写回，规避 `SWIFT_DEFAULT_ACTOR_ISOLATION=MainActor` 下的跨 actor 断言。本机无 iOS SDK 无法编译验证，需在 Xcode 真机/模拟器跑一次确认定位权限弹窗与 EXIF 写入正确。
